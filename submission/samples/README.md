# Sample buildings A to E: model, audit outputs and BCF

All five models are NIYAM's own **synthetic** test buildings (`fixtures/samples/`, generated by
`scripts/build_sample_buildings.py`); none is a real building. Each folder holds:

| File | What it is |
|---|---|
| `<name>.ifc` | the IFC4 model (copied from `fixtures/samples/`) |
| `<name>.truth.json` | the hand-written expected verdict of every element under every rule |
| `report.json`, `report.html` | the audit against rulepack v0 (6 draft rules) |
| `issues.bcf` | BCF 2.1 issues: one topic per failed or unchecked element |
| `summary.txt` | the CLI's per-rule table |

| Sample | Unit | Contents | Overall status |
|---|---|---|---|
| `sample_a_mm` | millimetre | 12 doors | noncompliant (17 passed, 6 failed, 7 unchecked, 6 out_of_scope checks) |
| `sample_b_m` | metre | 10 doors | noncompliant (14 passed, 4 failed, 6 unchecked, 6 out_of_scope checks) |
| `sample_c_no_fireexit_mm` | millimetre | 4 doors without FireExit | incomplete (0 passed, 0 failed, 12 unchecked checks): nothing can be checked |
| `sample_d_rooms_stairs_mm` | millimetre | 9 spaces, 5 stair flights | noncompliant (4 passed, 3 failed, 6 unchecked, 10 out_of_scope checks) |
| `sample_e_rooms_stairs_m` | metre | 8 spaces, 4 stair flights | noncompliant (3 passed, 3 failed, 5 unchecked, 9 out_of_scope checks) |

"noncompliant" and "compliant" are the audit engine's status names for the draft rules, not legal findings.

Regenerate (from `backend/`, venv active):

```bash
python -m app.audit.cli run ../fixtures/samples/sample_a_mm.ifc --out ../submission/samples/sample_a_mm
```

## BCF validation

`python scripts/validate_bcf.py submission/samples/*/issues.bcf --xsd <dir>` checks each file as a BCF 2.1 zip:
`bcf.version` at the root with `VersionId="2.1"`, one GUID folder per topic, `markup.bcf` with a matching Topic Guid,
and every viewpoint file it names. With `--xsd` pointing at buildingSMART's BCF 2.1 schemas
(`markup.xsd`, `visinfo.xsd`, `version.xsd` from https://github.com/buildingSMART/BCF-XML/tree/release_2_1/Schemas,
not committed), every XML file is also validated against them. Result on 25 November 2026:

| File | Topics | Viewpoints | Structure | XSD (markup, visinfo, version) |
|---|---|---|---|---|
| `sample_a_mm/issues.bcf` | 13 | 13 | OK | OK |
| `sample_b_m/issues.bcf` | 10 | 10 | OK | OK |
| `sample_c_no_fireexit_mm/issues.bcf` | 12 | 12 | OK | OK |
| `sample_d_rooms_stairs_mm/issues.bcf` | 9 | 9 | OK | OK |
| `sample_e_rooms_stairs_m/issues.bcf` | 8 | 8 | OK | OK |

Limits: the viewpoints carry component selections only, no camera and no snapshot (`docs/audit.md`), so viewers
that need a camera open the topic without flying to the element. The files were not opened in a third-party BCF
viewer here.
